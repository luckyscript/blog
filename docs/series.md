# 独立系列栏目

系列与生活文章是两套内容流程。顶部“系列”访问 `/series`，生活列表和普通文章后台不包含系列篇目。系列有独立的介绍、更新状态与公开 / 草稿设置，不再选择生活 / 技术等文章栏目。

- 系列入口：`/series/<series-slug>`。
- 独立篇目：`/series/<series-slug>/<note-slug>`。
- 后台系列管理：`/admin/series`；编辑篇目：`/admin/series/notes/<uuid>`。
- 系列编辑器使用独立目录、篇目信息、预览、云端草稿、本机恢复备份、版本记录及发布 / 撤回 / 回收站。正文编辑组件和媒体上传能力共用，不复用普通文章的数据模型或编辑地址。
- 系列入口不设置“读最新 / 从头读”大按钮，不使用对角箭头装饰符号。
- 独立 RSS：`/series/rss.xml`；普通生活 RSS 保持只收录普通文章。站点地图包含独立系列和篇目。

## 数据与一致性

`blog_series` 保存系列信息。`011_independent_series.sql` 创建 `blog_series_notes`、`blog_series_note_drafts`、`blog_series_note_revisions` 和 `blog_series_paths`，分别保存正文、草稿、历史版本和旧地址映射。

草稿保存不修改公开快照；发布在事务中校验版本、网址和正文并切换公开版本。重复的相同草稿保存不会重复递增版本。恢复历史只生成草稿，并额外保留恢复前内容；回收站可以恢复。系列为草稿时，该系列及其篇目均不对外展示。

## 原有内容迁移

先备份完整数据库，应用 `011_independent_series.sql`，再执行 `scripts/separate-series-storage.ts` 查看计划；`--apply` 才写入。迁移单事务复制所有原系列篇目、尚未发布的草稿和历史记录，保留原文、原始日期与版本号，校验并输出原文 SHA-256。遇到待发布的跨系列归属变更则停止，避免猜测作者意图。

旧文章记录保留归档，状态为 `series`，不进入普通文章列表、编辑和导出。新系列数据不再依赖旧文章行；旧入口、旧篇目及修改过的篇目网址通过专用映射跳转。历史关系表仅为归档资料，运行时不再用于系列读取。

迁移前数据库快照和旧发布版本必须保留。代码回滚时应同步恢复旧文章状态及原系列入口引用；不能仅回滚代码而保留迁移后的归档状态。
