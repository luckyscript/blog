# 系列手记

系列拥有标题、简介、所属栏目、入口可见性和“持续更新 / 已完结”状态。篇目沿用普通文章的草稿、版本、发布、图片、评论与备份流程，以 `metadata.seriesId` 表示归属，`metadata.seriesContext` 保存可选的场景或行程（最多 200 字）。

- `/series` 列出有已发布篇目的公开系列；`/series/<slug>` 为新系列入口。
- “乘客与司机”沿用 `/blog/2023/passenger-and-drivers`。其 `/series/passenger-and-drivers` 地址永久跳转至旧地址。
- 入口按发布时间倒序列出手记，不设“读最新 / 从头读”按钮。单篇包含系列出处、上一篇 / 下一篇和可展开的完整目录。
- `/blog` 显示系列入口；独立新篇继续进入普通文章列表、首页近期文章和 RSS。系列入口原稿不重复进入文章列表，站点地图保留入口和篇目。
- `/admin/series` 创建、编辑系列和“写新篇”；文章发布设置也能修改系列归属。归属修改只在文章发布事务内同步到 `blog_series_entries`，草稿不会提前更改公开目录。
- 系列草稿隐藏入口，但不会替作者撤回已发布的独立文章。文章草稿、回收站及未来发布时间均不进入公开目录。
- 修改设置需匹配版本号，文章栏目必须与系列一致，系列入口不能成为自身篇目。

## 迁移已有原文

运行 `scripts/db-setup.ts` 应用 `010_series.sql` 后，先执行 `node --import tsx scripts/migrate-driver-series.ts` 查看计划；`--apply` 才写入。

迁移限定当前原文中的三个已知二级标题，解析并验证每则原始日期。保留原文章记录、原文、日期、路径和已有评论；生成三篇带原始日期、行程、完整正文及迁移版本记录的独立文章。迁移前有未发布草稿、标题结构漂移、无效日期或网址冲突时停止。重复运行验证既有结果，不重复建篇。

部署前保留数据库快照与原文 SHA-256，迁移在单一事务中写入系列、文章和关系。代码回滚无需删除新内容；可将本次迁入的篇目及系列撤回为草稿，原稿始终保留。数据库完整备份会自动包含新增的两张表。
